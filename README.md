# Yandex Review Response Assistant — установка и запуск

Ассистент состоит из двух частей, которые работают в связке:

1. **`GigaChatReplyServer`** — локальное Windows-приложение (трей), которое поднимает веб-сервер на `http://localhost:5005` и генерирует ответы на отзывы через GigaChat API.
2. **`Extention`** — расширение для Chrome/Yandex Browser (Manifest V3), которое добавляет кнопку «✨ Сгенерировать ответ» на странице отзывов в Яндекс.Бизнесе и обращается к локальному серверу.

---

## Быстрый старт: готовый релиз (без сборки)

Собирать сервер из исходников не обязательно — на вкладке **[Releases](../../releases)** этого репозитория лежит готовый self-contained архив (не требует установленного .NET).

1. Откройте вкладку Releases репозитория и скачайте последний `GigaChatReplyServer-vX.X-win-x64.zip`.
2. Распакуйте архив в любую папку.
3. Откройте `appsettings.json` и впишите свой `AuthKey` от GigaChat (как его получить — см. п. 3.1 ниже).
4. Запустите `GigaChatReplyServer.exe` — появится иконка в трее, сервер поднимется на `http://localhost:5005`.
5. Установите расширение браузера — см. раздел 4.

Разделы 1–3 ниже описывают сборку **из исходников** — актуально, если хотите что-то поменять в коде или собрать релиз самостоятельно.

---

## 1. Требования

- Windows 10/11 (сервер использует WinForms и запускается как трей-приложение).
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) — нужен только для сборки из исходников. Если используете готовый релиз из раздела выше, .NET ставить не нужно.
- Chrome или Yandex Browser (для расширения).
- Аккаунт разработчика GigaChat (Сбер) для получения API-ключа: https://developers.sber.ru/portal/products/gigachat.

## 2. Скачивание и распаковка

1. Скачайте архив репозитория с GitHub (Code → Download ZIP).
2. Распакуйте архив в любую папку, например `C:\Assistant`.

## 3. Настройка и запуск сервера (GigaChatReplyServer)

Перейдите в папку сервера:

```
cd GigaChatReplyServer\GigaChatReplyServer
```

### 3.1. Получите ключ авторизации GigaChat

В личном кабинете GigaChat создайте проект/API-ключ (Client ID + Client Secret), сформируйте из них `Authorization key` (base64-строка), как описано в документации GigaChat API. Также определитесь со `Scope`:
- `GIGACHAT_API_PERS` — для физлиц (уже стоит по умолчанию),
- `GIGACHAT_API_B2B` / `GIGACHAT_API_CORP` — для юрлиц.

### 3.2. Заполните конфигурацию

Откройте `appsettings.json` и замените плейсхолдер:

```json
"GigaChat": {
  "AuthKey": "ВАШ_РЕАЛЬНЫЙ_КЛЮЧ_АВТОРИЗАЦИИ",
  "Scope": "GIGACHAT_API_PERS",
  "Model": "GigaChat-3-Ultra",
  "ChatContextFile": "chatContext.txt"
}
```

При необходимости откройте `chatContext.txt` и добавьте туда системный контекст/инструкции для модели (тон ответов, стиль компании и т.п.) — сейчас там просто заглушка.

### 3.3. Запуск в режиме разработки

```
dotnet restore
dotnet build
dotnet run
```

Приложение свернётся в трей (иконка рядом с часами), поднимет сервер на `http://localhost:5005`. Swagger доступен по `http://localhost:5005/swagger`.

### 3.4. Публикация релиза через Visual Studio 2022 (запуск без установленного .NET)

Чтобы получить архив, который запускается на чужой машине без установленных dotnet-инструментов, нужна self-contained публикация в один exe-файл. В проекте уже есть готовый профиль публикации.

1. Откройте `GigaChatReplyServer.sln` в Visual Studio 2022, выберите конфигурацию **Release**.
2. Перед публикацией впишите реальный `AuthKey` в `appsettings.json` (и при необходимости содержимое `chatContext.txt`) — эти файлы попадут в архив как есть. Если архив предназначен не только для вас, учтите, что ключ окажется в открытом виде внутри zip.
3. В **Solution Explorer** → правой кнопкой по проекту `GigaChatReplyServer` → **Publish**. VS должен подхватить существующий профиль `FolderProfile` (`Properties/PublishProfiles/FolderProfile.pubxml`).
4. Откройте настройки профиля (⚙️ **Edit**/«Show all settings») и проверьте:
   - **Deployment mode:** Self-contained
   - **Target runtime:** win-x64
   - ☑ Produce single file
   - ☐ Trim unused assemblies — **оставьте выключенным** (Swashbuckle и reflection-based сериализация могут сломаться при обрезке)
   - ☑ Enable ReadyToRun compilation — опционально, ускоряет старт ценой размера файла
5. **Save** → **Publish**. По завершении нажмите **Open folder** — попадёте в:
   ```
   bin\Release\net8.0-windows\win-x64\publish\
   ```
6. В папке публикации должны быть: `GigaChatReplyServer.exe` (единственный исполняемый файл), `appsettings.json`, `appsettings.Development.json`, `chatContext.txt`. Отдельного `app.ico` не будет — иконка встроена в exe.
7. Перед архивацией проверьте запуск `GigaChatReplyServer.exe` на машине без установленного .NET (или временно переименуйте папку `C:\Program Files\dotnet`) — self-contained публикация должна работать сама по себе.
8. Заархивируйте содержимое папки `publish` целиком, например в `GigaChatReplyServer-v1.0-win-x64.zip`. Исходный код в архив класть не нужно.

**Инструкция для того, кто будет распаковывать архив:**
1. Распаковать в любую папку.
2. Открыть `appsettings.json` и вписать свой `AuthKey` (если не сделали это заранее).
3. Запустить `GigaChatReplyServer.exe` — появится иконка в трее, сервер поднимется на `http://localhost:5005`. Устанавливать .NET не требуется.

## 4. Установка расширения браузера

1. Откройте `chrome://extensions` (в Yandex Browser — `browser://extensions`).
2. Включите «Режим разработчика» (переключатель в правом верхнем углу).
3. Нажмите «Загрузить распакованное расширение» и укажите папку `Extention` из архива.
4. Расширение появится в списке под именем «Yandex Review Response Assistant».

### 4.1. Настройка адреса сервера

По умолчанию расширение обращается к `http://localhost:5005` — адресу, на котором поднимается `GigaChatReplyServer`. Менять его нужно только если вы вручную изменили порт сервера.

Чтобы открыть настройки — кликните по иконке расширения на панели инструментов браузера (для неё настроен всплывающий попап с полем адреса) или зайдите через `chrome://extensions` → карточка расширения → «Параметры расширения».

1. Проверьте/поправьте значение в поле «Адрес локального сервера GigaChatReplyServer».
2. Нажмите «Сохранить». Допускаются только адреса вида `http://localhost:PORT` или `http://127.0.0.1:PORT` — так и должно быть, сервер не предназначен для работы через интернет.

## 5. Использование

1. Убедитесь, что `GigaChatReplyServer` запущен (иконка в трее).
2. Откройте страницу редактирования отзывов в Яндекс.Бизнесе: URL вида
   `https://yandex.ru/sprav/*/p/edit/reviews/*`.
3. Кликните в пустое поле ответа — появится кнопка «✨ Сгенерировать ответ».
4. Нажмите кнопку — откроется панель предпросмотра с сгенерированным текстом, который можно отредактировать.
5. Кнопки в панели:
   - **Вставить** — подставляет текст в поле ответа.
   - **Сгенерировать заново** — повторный запрос к серверу.
   - **Отмена** — закрыть панель.

## 6. Диагностика проблем

- Если после клика на «Сгенерировать ответ» появляется сообщение об ошибке сервера — проверьте, что трей-приложение запущено и слушает порт 5005 (не занят ли порт другим процессом).
- Расширение работает только на точном шаблоне URL из `manifest.json` (`host_permissions`/`content_scripts` ограничены `yandex.ru/sprav/*/p/edit/reviews/*` и `localhost:5005`). Для других доменов нужно будет расширить `manifest.json`.
- CORS на сервере открыт полностью (`AllowAnyOrigin`) — это нормально для локальной разработки, но не стоит выставлять сервер наружу в интернет в таком виде.

## 7. Обновление сервера и расширения (v0.5.1)

**GigaChatReplyServer:**
- Удалён неиспользуемый `config.txt` (нигде не читался кодом — подтверждено поиском по решению) и соответствующая запись `<None Update="config.txt">` в `.csproj`.
- В `.csproj` добавлена запись `<None Update="chatContext.txt">` с `CopyToPublishDirectory` — раньше этот файл не копировался при publish, из-за чего опубликованный релиз не находил его на диске.

**Extention:**

- Убрано неиспользуемое поле «API-ключ OpenRouter» из настроек — оно ни на что не влияло.
- Вместо него настройки хранят **адрес локального сервера** (`serverUrl` в `chrome.storage.local`), который реально используется при каждом запросе генерации.
- `manifest.json`: `host_permissions` больше не привязаны жёстко к порту `5005` (`http://localhost/*`, `http://127.0.0.1/*`) — можно сменить порт сервера без правки манифеста и переустановки расширения.
- Добавлен `default_popup` — настройки теперь открываются кликом по иконке расширения, а не только через страницу `chrome://extensions`.
- Если сервер недоступен, панель предпросмотра теперь показывает, к какому именно адресу расширение пыталось обратиться — это упрощает диагностику.
- **Исправлен баг** в `matches` (`manifest.json`): паттерн `.../reviews/*` требовал обязательный `/` сразу после `reviews`, из-за чего расширение не запускалось на страницах вида `.../edit/reviews?ncrnd=...` (без завершающего слэша перед query-строкой). Теперь используется `.../reviews*`, который ловит страницу независимо от завершающего слэша.

Если вы обновляете уже установленное расширение — замените файлы `manifest.json`, `content.js`, `options.html`, `options.js` в папке `Extention` на новые версии и нажмите «Обновить» на странице `chrome://extensions` (кнопка со стрелкой по кругу на карточке расширения, либо просто перезагрузите расширение).
